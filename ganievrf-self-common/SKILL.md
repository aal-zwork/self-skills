# ganievrf-self-common

Хаб-документ, не привязанный к конкретной задаче. Назначение: когда
появляется **новый** issue, касающийся ADM-машины/секретов/k8s-рантайма
агентов — быстро подтянуть уже накопленные знания об архитектуре по дереву
скиллов ниже, не изучая всё заново.

## Дерево скиллов

```
ganievrf-self-common        (вы здесь — хаб, список и связи)
├── ganievrf-self-adm       — как работать с ADM-машиной (ssh, bootstrap, disaster recovery)
├── ganievrf-self-secrets   — модель секретов (pass+S3+GPG VM-ключи, provider layout)
├── ganievrf-self-ansible   — структура ролей/плейбуков, provider abstraction, agent_runtime_scaffold
└── ganievrf-self-skills    — конвенции самого набора скиллов (языки, naming, когда дополнять)
```

## Что это за инфраструктура

- Одна ADM-машина (`ssh yandex-cloud-adm`), сервис-аккаунт которой уже имеет
  admin-права в Yandex Cloud.
- Через неё — доступ к управляемому k8s-кластеру в Yandex Cloud, изолированному
  от интернета.
- Секреты (облачные и внешние) — через `pass` (passwordstore.org),
  синхронизация с S3; GPG-ключи выпускаются с локального мастер-ключа per-VM.
- Три репозитория (сейчас — подпапки одной задачи `ISSUE-GANIEVRF-0`, в
  будущем — отдельные GitHub-репо): `ansible`, `secrets`, `skills`.
- Провайдер S3/k8s сейчас — Yandex Cloud, но архитектура закладывает замену
  провайдера (см. `ganievrf-self-ansible` и `ganievrf-self-secrets`).
- Рантайм агентов в k8s — кандидат [ecc](https://github.com/aal-zwork/ecc),
  интеграция не завершена (открытые вопросы — в `docs/ecc-integration-todo.md`
  соответствующей задачи).

## Когда дополнять этот скилл

Каждый раз, когда появляется новый `ganievrf-self-*` скилл за рамками
текущей задачи — добавить его в дерево выше в том же изменении.
